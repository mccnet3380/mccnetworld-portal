[수정 원칙 — 매우 중요]
1) 오류가 발생한 부분의 코드만 수정하라.
2) UI(레이아웃/디자인/스타일/컴포넌트 구조)는 절대 변경 금지.
3) .env, Secrets, DB 접속 계정/비밀번호/호스트 값은 절대 코드에 하드코딩하지 말라.
   - 연결 문자열은 오직 process.env.DATABASE_URL 에서만 읽어라(값은 내가 설정함).
4) 부분 코드 금지. 반드시 “파일 전체 최종본”을 반환하라.
5) 내가 즉시 복붙할 수 있어야 한다(설명은 아주 간단히만).
6) 해석/추측 금지. 실제 타임아웃/연결 에러를 재현하고 필요한 최소 범위만 고쳐라.
7) 모든 코드 수정이 끝난 후 반드시 서버를 재시작하여 적용 결과를 확인할 것.
8) 수정 완료 후, 동일 시나리오에서 코드 이상/에러가 없는지 반드시 재검증할 것.

[현재 상황]
- 애플리케이션 로직(CSV 업로드/영업과장 조회/중복체크 등)은 정상.
- 단, PostgreSQL(Neon) 연결이 10초 후 타임아웃으로 실패. 특정 IP(예: 18.142.152.125, 3.0.216.9, 13.214.97.86)에 TCP 연결 불가.
- 코드 문제보다는 네트워크/인프라 이슈로 보이나, 코드 측에서 진단/복구력을 강화해야 함.

[해야 할 일 — 진단 & 견고화]
A) DB 클라이언트(현재 사용하는 스택: pg/Prisma/Sequelize/TypeORM 중 실제 프로젝트 기준) 연결 옵션 보강
   - 연결/쿼리 타임아웃, keepAlive, SSL 요구, IPv4 우선(가능 시) 설정.
   - 예시(라이브러리별 실제 옵션으로 적용):
     - connectionTimeoutMillis/statement_timeout/idleTimeoutMillis 보강(연결 10→30초, 쿼리 타임아웃 30→60초 수준)
     - keepAlive: true
     - SSL: require (Neon 권장). DATABASE_URL에 ?sslmode=require 가 없으면 **코드에서 런타임에만** 붙여서 사용(하드코딩 금지).
     - DNS lookup을 사용할 수 있으면 family:4 로 IPv4 우선 적용(가능한 범위에서만).
   - 초기 연결 및 1회성 쿼리에 대해 **지수 백오프 재시도(최대 3회)** 적용:
     - 재시도 대상 에러코드: ETIMEDOUT, ECONNRESET, ENOTFOUND, EAI_AGAIN 등 네트워크형
     - 백오프: 0.5s → 1s → 2s

B) 헬스체크/진단 엔드포인트 추가 (운영용 도구)
   - GET /health/db : `SELECT 1` 실행 후 { ok: true, latencyMs, resolvedHost, usedIPv: 4|6 } 형태 JSON 반환
   - DNS 해석 결과(호스트→IP), 연결까지 걸린 시간, SSL 사용 여부, 마지막 에러코드/메시지를 로깅(Secrets 노출 금지)
   - 실패 시 { ok: false, errorCode, step } 로 최소 정보만

C) 독립 진단 스크립트 추가(콘솔 실행용)
   - scripts/db_health.(ts|js) : DATABASE_URL만 사용하여
     1) DNS resolve
     2) TCP connect
     3) SSL handshake
     4) `SELECT 1`
     를 순서대로 시도하고, 각 단계 latency/에러코드 출력. 재시도(3회) 포함.
   - 실행 예: `npm run db:health` (package.json 스크립트 추가)

D) 쿼리 래퍼(선택, 최소 범위)
   - 주요 DB 호출부에 한해, 네트워크성 에러에만 1~2회 재시도 래퍼 적용(비즈니스 로직 변경 금지).

[검증]
- 서버 재시작 후 /health/db 호출 시 성공/실패가 명확히 보이고, 성공 시 latency와 IPv4/IPv6, SSL 요구 여부가 출력.
- 진단 스크립트 `npm run db:health` 실행 시, 현 환경에서 타임아웃/연결 실패가 재현되면 재시도 로그와 에러코드가 보인다.
- 네트워크가 안정적일 때는 애플리케이션의 CSV 업로드/조회/저장이 정상 동작.
- Secrets/DATABASE_URL은 코드에 노출되지 않음.
