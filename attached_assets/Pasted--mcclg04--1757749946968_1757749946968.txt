[구체 작업 지시]

A) 역할/권한(UI) 전환 버그(리프레시 시 역할 오표기/충돌) 수정
- 증상: mcclg04로 로그인 후 새로고침하면 영업과장 UI가 어긋나거나 원세영의 권한/이름과 충돌하는 것처럼 보임.
- 반드시 확인 및 수정:
  (1) **서버의 /api/auth/me 응답**: 토큰 파싱 결과의 role/userType, userId(또는 sub)가 DB와 일치하는지.
  (2) **로그인/리프레시 토큰 생성 로직**: payload에 role, userType, userId, dealerId/managerId 등이 **일관되게** 들어가고 있는지.
  (3) **프런트 상태 저장(Zustand 등)**: localStorage/persist에 저장된 role과 서버 me 응답 간 불일치가 없는지. 새로고침 시 **반드시 서버 me 응답으로 최종 동기화**하여 UI를 결정하도록 보장.
  (4) 사용자 식별 키(userId/username)가 **캐시/스토리지에 남은 다른 사용자(원세영) 값으로 덮여쓰이지 않도록** 모듈 전역 상태, 키 이름 충돌, race condition 제거.
  (5) 매 요청 시 Authorization 헤더(AccessToken)가 제대로 갱신되어 서버 me가 올바른 사용자를 반환하도록 확인.
- 목표: 새로고침 후에도 mcclg04는 항상 **영업과장 UI**로 렌더링되며, 다른 사용자 정보와 혼동되지 않는다.

B) 개통완료 목록의 요금제 **검색/선택** 기능(미반영 재작업)
- “접수신청” 화면에서 사용 중인 **통신사별 필터 + 검색 가능한 요금제 선택 로직/컴포넌트**를 **동일하게 재사용**하라.
- 우선순위
  1) 공용 컴포넌트(예: PlanSelect/RatePlanSelect)가 있으면 그대로 import하여 사용.
  2) 공용 훅/서비스(예: useRatePlans/fetchRatePlansByCarrier)를 재사용.
  3) 없으면 “접수신청”과 동일 API/동일 필터/동일 debounce 검색만 복제 구현(레이아웃/스타일 변경 금지).
- 선택 결과는 기존 저장 필드(예: servicePlanId/ratePlanId/planName 등 프로젝트 실제 필드)에 정확히 반영.

C) 개통취소 처리(미반영 재작업) + 사이드바 메뉴 제거
- “개통취소” 버튼 클릭 시:
  - 별도 카테고리/테이블로 이동시키지 말고, **개통완료 테이블의 ‘개통취소일’ 컬럼(canceled_at 등)** 에 **버튼 클릭 시각(서버 시간, Asia/Seoul)** 을 저장.
  - 목록의 “개통취소일” 컬럼에 즉시 반영되도록 조회 쿼리/리스트 상태 갱신.
- **사이드바의 ‘개통취소 내역’ 메뉴를 제거**하고, 기존에 그 메뉴로 연결되던 기능은 위 방식(동일 테이블 내 canceled_at 업데이트)에 흡수된다.
  - 이 UI 변경(사이드바 메뉴 제거) **한 건만** 이번 요청에서 예외적으로 허용한다. 다른 UI는 절대 변경 금지.

D) “기타 완료” 집계/매칭 검증
- ‘기타 완료’로 집계되는 상태 enum/코드의 집합을 **서버 상수로 단일 정의**하고, 대시보드/리스트/카드 등에서 **동일 상수**를 참조하도록 정리.
- 오늘/당월 카드 및 상세현황 집계에서 ‘기타 완료’가 누락되거나 과다 집계되지 않게 쿼리 수정.

E) 토스트 노출시간 3초 고정(재점검)
- 사용중인 토스트 라이브러리의 전역 기본 duration을 **3000ms** 로 통일.
- 개별 호출부에서 duration이 다른 값으로 지정된 경우 3000ms로 맞추거나 공용 wrapper 기본값 3000ms로 강제.
