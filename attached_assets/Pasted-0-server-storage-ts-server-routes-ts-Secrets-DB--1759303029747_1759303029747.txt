1) 문제 요약(현재 상태)

개통완료 목록에 10/01 건들, 처리자 정상.

대시보드의 “당일 접수/개통, 당월 개통 현황”은 0 고정.

원인: KST 기준 집계 미적용 + 집계 컬럼 혼용 + 서버 응답 키가 프론트 기대와 불일치.

2) 반드시 이 방식으로 고정 구현
A. 집계 기준(반드시 이 기준)

당일 접수 = uploaded_at 기준(Asia/Seoul 하루 범위)

당일/당월 개통 = activated_at 기준(Asia/Seoul) +
activation_status IN ('개통완료','기타완료')

권한 필터:

근무자: 본인(업로드/개통자)만

영업과장: 팀 범위

관리자: 전체

B. ORM 우회(드리즐 타임존 이슈 회피)

JavaScript 쪽에서 시간 보정/비교 금지.

반드시 DB에서 KST 경계를 만든 뒤 UTC로 비교하세요. Drizzle의 sql 템플릿로우 사용.

당일 KST 범위(UTC 비교값)

-- start/end of today in KST, converted to UTC for column comparison
(DATE_TRUNC('day', NOW() AT TIME ZONE 'Asia/Seoul')        AT TIME ZONE 'UTC')  -- start_utc
((DATE_TRUNC('day', NOW() AT TIME ZONE 'Asia/Seoul') + INTERVAL '1 day') AT TIME ZONE 'UTC')  -- end_utc


예시 (당일 개통 건수)

SELECT COUNT(*) FROM documents d
WHERE d.activated_at >= start_utc
  AND d.activated_at <  end_utc
  AND d.activation_status IN ('개통완료','기타완료');


월별/통신사/근무자 통계도 동일 원칙(집계 기준은 activated_at KST).
월별은 date_trunc('month', activated_at AT TIME ZONE 'Asia/Seoul')로 그룹핑, 최근 6개월 제한.

C. 프론트 기대 응답 키로 정규화

프론트 수정 금지. 서버가 키를 맞춥니다.

client/src에서 grep으로 실제 참조 키명을 뽑아 그 키로 반환:

명령(예):
rg -n "today|today-stats|carrier-stats|worker-stats|monthly-activation" client/src -C 3

일반적으로 아래와 유사(프로젝트에 실제 값으로 매핑):

todayReceived, todayCompleted, todayCompletedNew, todayCompletedPort, otherCompletedToday

monthlyActivationStats: [{ label:'YYYY-MM', total, new, port }]

carrierStats: [{ carrier, count }]

workerStats: [{ workerName, count }]

D. 사용자 컨텍스트 안전 추출(라우트 공통)
const ctx = (req as any).user
         || (req.session as any)?.user
         || { userId: (req.session as any)?.userId, userType: (req.session as any)?.role };
const userId   = ctx?.id ?? ctx?.userId ?? null;
const userType = ctx?.type ?? ctx?.userType ?? (req.session as any)?.role ?? 'admin';


근무자/팀/전체 필터는 서버에서 강제(클라 파라미터 무시).
