[승인/지시] activated_by_role 방식으로 처리자 충돌 근본 해결 (변동 최소)

목적(한 줄)
- documents에 역할 컬럼 1개만 추가(activated_by_role)하고, 역할 분기 JOIN으로 Super Admin ↔ L)수정 중복 집계/표기를 제거한다.

변경 범위(최소)
- 스키마: 컬럼 1개 추가 (VARCHAR(10): 'admin' | 'user')
- 서버: 쓰기 시 역할 세팅, 읽기/집계 시 역할 분기 JOIN
- 프론트/환경/스타일: 변경 없음

1) 스키마 추가 (shared/schema.ts)
```ts
// documents 스키마에 추가
activatedByRole: varchar('activated_by_role', { length: 10 })  // 'admin' | 'user'
쓰기 로직 수정 (server/routes.ts)
대상 엔드포인트:

PUT /api/documents/:id

PATCH /api/documents/:id/activation-status

규칙:

기존 activatedBy 보존 로직은 유지(이미 개통된 건은 변경 금지)

신규로 설정해야 하는 경우에만, 세션 역할로 role 세팅

ts
코드 복사
const role = req.session?.role === 'admin' ? 'admin' : 'user';
if (settingActivatedBy && !existingDoc?.activatedBy) {
  updateData.activatedBy = req.session?.userId;
  updateData.activatedByRole = role;    // ✅ 역할 기록
}
조회/집계 로직 수정 (server/storage.ts)
모든 “처리자” 표기/집계 쿼리에 역할 분기 JOIN 적용:

ts
코드 복사
query = db.select({
  ...docColumns,
  activatedByName: sql<string>`
    CASE
      WHEN documents.activated_by_role = 'admin' THEN ${admins.name}
      WHEN documents.activated_by_role = 'user'  THEN ${users.name}
      ELSE NULL
    END
  `,
})
.leftJoin(admins, and(
  eq(documents.activatedBy, admins.id),
  sql`documents.activated_by_role = 'admin'`
))
.leftJoin(users, and(
  eq(documents.activatedBy, users.id),
  sql`documents.activated_by_role = 'user'`
));
※ 개통완료 목록·대시보드 통계 등 처리자 참조 쿼리 전부 동일 원칙으로 통일.

마이그레이션 (SQL, 두 단계)

dev(Neon) → 확인 후 prod(Render)에 실행

(1) 컬럼 추가

sql
코드 복사
ALTER TABLE documents
  ADD COLUMN activated_by_role VARCHAR(10) NULL;
(2) 자동 백필(충돌 없는 행만)

sql
코드 복사
-- admin만 존재
UPDATE documents d
   SET activated_by_role = 'admin'
 WHERE d.activated_by IS NOT NULL
   AND EXISTS (SELECT 1 FROM admins a WHERE a.id = d.activated_by)
   AND NOT EXISTS (SELECT 1 FROM users  u WHERE u.id = d.activated_by);

-- user만 존재
UPDATE documents d
   SET activated_by_role = 'user'
 WHERE d.activated_by IS NOT NULL
   AND EXISTS (SELECT 1 FROM users u WHERE u.id = d.activated_by)
   AND NOT EXISTS (SELECT 1 FROM admins a WHERE a.id = d.activated_by);
(3) 충돌 리포트(수동 지정 대상)

sql
코드 복사
SELECT d.id AS document_id, d.activated_by
  FROM documents d
 WHERE d.activated_by IS NOT NULL
   AND EXISTS (SELECT 1 FROM admins a WHERE a.id = d.activated_by)
   AND EXISTS (SELECT 1 FROM users  u WHERE u.id = d.activated_by);
→ 리포트 CSV 생성 후, 관리자가 각 문서의 실제 처리자 역할을 지정해 activated_by_role 업데이트.
