배경

현재 Replit(개발 환경) 부팅 로그에 DATABASE_URL=.../neondb 및 documents_count=77이 출력되었습니다. 이는 운영 DB에 붙었다는 증거입니다.

우리는 이미 개발 DB와 운영 DB를 분리하여 사용 중입니다.

따라서 개발 환경이 운영 DB를 참조하는 잘못된 설정을 즉시 수정하고, **운영 서버에는 최신 코드(‘기타완료’ 포함)**를 반영하세요.

반드시 수행할 작업 (운영·개발 각각)
1) 서버 시작 로그에 환경/DB 정보 강제 출력 후 캡처 제출

서버 시작 직후 아래 정보가 콘솔에 반드시 찍히도록 하고 캡처 제출:

NODE_ENV, APP_ENV

마스킹한 DATABASE_URL (예: postgresql://user:****@host:5432/db)

dotenv 로딩 경로(예: .env.development / .env.production) 또는 ENV 로딩 방식

시작 타임스탬프

예시 로그 포맷

[BOOT] Started at: 2025-10-02T06:51:14.776Z
[BOOT] NODE_ENV=development
[BOOT] APP_ENV=development
[BOOT] DATABASE_URL=postgresql://neon_user:****@ep-dev-xxx.neon.tech:5432/dev_db
[BOOT] dotenv: .env.development


중요: Replit(개발) 로그에 운영 DB 이름/호스트가 절대 찍히면 안 됩니다.

2) 실제 접속 DB 증빙 SQL 실행 및 결과 제출 (앱이 쓰는 커넥션으로)

운영/개발 각 환경에서 아래 SQL을 실행하고 결과 텍스트/스크린샷 제출:

SELECT current_database()   AS db,
       current_user         AS "user",
       inet_server_addr()   AS host,
       inet_server_port()   AS port;

SELECT COUNT(*) AS documents_count FROM documents;


기대: dev와 prod의 db/host/port 또는 documents_count가 명확히 다름.

3) 개발 환경(DB) 수정 지시

Replit(개발)에서 반드시 개발 DB로 연결되도록 설정 변경:

Replit Secrets에 DATABASE_URL_DEV(개발 DB), DATABASE_URL_PROD(운영 DB) 분리 보관

개발 서버 실행 스크립트가 DATABASE_URL_DEV만 로드하도록 보장

.env.development(또는 ENV 로딩 코드)에서 개발 DB만 참조하게 설정

설정 후 서버 완전 재시작(hot reload 금지; 프로세스 재기동)

이후 ①부팅 로그, ②SQL 결과 다시 제출.

4) 운영 서버 최신 코드 반영 (기타완료 옵션 포함)

운영 서버에서 아래 절차 수행 및 로그/해시 증빙 제출:

git rev-parse HEAD      # 배포 전 커밋 해시
git pull origin main    # 최신 코드 반영
npm ci
npm run build
# 프로세스 매니저별 재시작
pm2 restart all || docker compose restart || systemctl restart <service>
git rev-parse HEAD      # 배포 후 커밋 해시


브라우저 캐시 초기화(Application → Clear storage → Clear site data, 강력 새로고침) 후 운영 UI 스크린샷 제출:

접수관리 → “개통 상태 변경” 모달 드롭다운에 ‘기타완료’ 표시

대시보드 → ‘기타 업무 처리건’ 집계 정상 표시

변경/금지 범위(필수 준수)

DB 스키마 변경 금지

환경변수 키 충돌 금지(dev/prod는 서로 다른 키로 관리)

UI/레이아웃/디자인/스타일 변경 금지

운영 DB/개발 DB 절대 공유 금지

완료 후 제출해야 할 증빙물

운영/개발 각각의 부팅 로그 캡처(ENV/DB 마스킹 포함)

운영/개발 각각의 SQL 결과 캡처/텍스트

운영 서버 배포 로그(커밋 해시 전/후, 빌드/재시작 기록)

운영 UI 스크린샷

접수관리 드롭다운에 ‘기타완료’ 표시

대시보드 ‘기타 업무 처리건’ 반영

이번 작업에서 변경한 파일 경로/커밋 해시 목록

실패 시 즉시 조치

Replit(개발)이 여전히 운영 DB로 붙는 경우:

Replit Secrets의 DATABASE_URL 값을 개발 DB URL로 교체

서버 완전 재시작

1)~2) 로그/SQL 증빙 재제출
