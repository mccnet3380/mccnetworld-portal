변경 개요
관리자 패널 핵심 실패 3건(접수 파일 업로드 400, 개통완료 목록 필터 누락, 메뉴 텍스트 불일치) 최소 수정으로 복구

수정 목적(한 줄)
업무 흐름 막는 3개 오류를 재현–수정–검증해 정상 운영 상태로 회복

해결할 오류 / 재현 절차(간단)

접수 업로드 400: 접수 신청 → 파일 선택 → 제출 → “Upload failed with status 400” (서버 로그 Files: [] 확인)

개통완료 목록 누락: 접수 관리 → 개통완료 처리 → ‘개통완료 관리’ 진입 → “문서 없음” 표시(필터 미적용)

메뉴 텍스트 불일치: 사이드바 ‘개통완료’ vs 화면/요구안 ‘개통완료 관리’, ‘기타업무접정’ 오타

변경 범위 요약
백엔드(우선): 파일 업로드 파싱/저장, 개통완료 조회 필터 보정
프론트(텍스트만): 사이드바/탭 표시 문자열 수정
빌드/배포: 변경 없음

수정 파일 목록 (최소화)

server/routes.ts — 업로드 엔드포인트(FormData/BASE64 겸용 파싱, 디버그 로그 정리), 개통완료 조회 조건 보강

server/storage.ts — 조회 보조 메서드 누락 시 안전가드/헬퍼만 추가(로직 변경 최소)

client/src/components/Sidebar.tsx — 메뉴명 텍스트 교정(레이아웃/스타일 불변)

파일별 변경 이유 (1–2줄)

routes.ts: formidable가 파일을 놓치는 케이스 처리(파일·BASE64 모두 허용), activationStatus='개통' 정확 매칭

storage.ts: contactCode/매장명 매핑 시 null 안전 처리만 보강(기존 쿼리/스키마 불변)

Sidebar.tsx: 표시 텍스트만 요구안과 일치화

예상 변경 내용 (요약 diff)

routes.ts
• 업로드: files.file(multipart) OR fields.file(base64) → 단일 저장 로직으로 normalize
• 업로드 실패 시 400→원인 메시지 포함, 성공 시 200 + documentId 반환
• 개통완료 조회: activationStatus === '개통' 강제, 날짜/통신사 필터 공존 시 and 조건 유지

storage.ts
• 매장명: COALESCE(real_sales_pos, dealer_name) 안전 반환(없으면 빈 문자열)

Sidebar.tsx
• '개통완료' → '개통완료 관리'
• '기타업무접정' → '기타업무접점'
