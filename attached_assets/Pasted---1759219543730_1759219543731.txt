수정 목적(한 줄)

기타 업무 통신사 / 사용자 / 요금제 생성 기능이 동작하지 않는 문제를 최소 변경 범위로 복구(엔드포인트 불일치 및 라우트 누락 정정, 응답 포맷 호환 유지).

해결할 오류 / 재현 절차(간단)
현재 증상

기타 업무 통신사 생성: 클릭 시 404/무반응

사용자 생성: 제출 시 404/무반응

새 요금제 추가: “생성” 클릭 시 무반응

재현

관리자 로그인 → AdminPanel 각 섹션에서 “생성” 실행

DevTools Network: 404 / 405 / CORS 또는 응답 스키마 불일치 확인

콘솔에 “API route not found” / “Unexpected response shape” 등 오류

근본 원인(로그/내용 기반)

프론트가 기대하는 기존 경로와 현재 서버 실제 경로가 불일치하거나 일부 라우트 누락

일부 환경에서 응답 포맷 변경(객체 직접 반환 vs { success, data } 래핑)으로 프론트 파싱 실패

기대 결과

각 생성 요청이 200/201로 정상 응답

목록 갱신(캐시 무효화) 후 새 레코드가 즉시 표시

콘솔 오류 0, 동일 시나리오 재실행 시 정상 동작

변경 범위 요약

백엔드(필요 최소)

엔드포인트 불일치 해소: 프론트가 현재 사용 중인 경로를 유지. 이미 /api/admin/...로 변경된 경우, **기존 경로에 Alias(프록시 라우트)**만 추가(리네임/대규모 수정 금지).

라우트 누락 시: 해당 POST 라우트만 최소 구현(입력 검증은 기존 수준 유지).

응답 포맷: 프론트가 기대하는 기존 포맷 그대로 유지(변경 금지).

프론트엔드(필요 최소)

AdminPanel에서 호출하는 경로가 현재 서버 실제 경로와 다를 경우에 한해 한 줄 치환으로 맞춤.

성공 후 invalidateQueries 또는 로컬 목록 prepend 등 기존 갱신 방식 유지.

빌드/배포: 프론트 빌드, 서버 재시작 필요

명시: .env/Secrets/DB 연결/운영 DB 로직, DB 스키마, 레이아웃/디자인/Tailwind/컴포넌트 구조 모두 미변경.

수정 파일 목록 (최소화)

프론트엔드

client/src/pages/AdminPanel.tsx（엔드포인트 문자열 불일치 시에만 최소 치환, 핸들러 바인딩/응답 파싱 유지）

(필요 시) client/src/lib/api.ts（경로 상수만 사용하는 경우 1곳 치환)

실제 레포 구조에 맞춰 존재하는 파일만 터치. 불필요 변경 금지.

파일 경로 + 파일별 변경 이유 (각 1–2줄)

**server/**routes.ts: 프론트가 호출하는 기존 경로(예: /api/service-plans, /api/other-business-carriers, /api/auth/users 또는 /api/auth/create-admin)가 동작하도록 라우트 누락 보완 또는 Alias 추가(호환성 유지).

AdminPanel.tsx: 현재 코드가 /api/admin/... 등으로 바뀌어 있다면 원래 경로로 복귀 또는 서버 Alias 존치 시 변경 불필요. 응답 파싱 로직은 기존 포맷 기준 유지.

예상 변경 내용 (요약 diff)

라우트 경로

변경 금지 원칙상, 프론트가 이미 사용하던 경로를 기준으로 서버를 맞춤.

만약 서버가 /api/admin/service-plans 등으로 바뀌어 있다면:

선호: 서버에 /api/service-plans → /api/admin/service-plans Alias 라우트 추가

차선: AdminPanel의 경로 상수 한 줄 치환(해당 섹션만)

응답 포맷

프론트 기대 포맷이 { success: true, data: {...} }라면 그대로 반환(서버에서 객체 직접 반환 금지).

이미 서버 응답을 바꾸었다면, 해당 3개의 생성 응답만 기존 포맷으로 복구.

캐시 무효화

성공 시 기존 쿼리키로 invalidateQueries 호출 유지(키 변경 금지).

핵심 추가/삭제/치환 포인트

추가: (필요 시) Alias 라우트만 추가해 경로 호환성 확보

치환: (불가피 시) AdminPanel 엔드포인트 문자열 한 줄만 기존 경로로 치환

유지: 응답 포맷, 쿼리키, 레이아웃/스타일, 컴포넌트 구조, DB 스키마, 환경설정 모두 불변

삭제 없음: 기존 코드/스타일 요소 제거 금지

환경변수/DB/스키마/스타일 미변경

✅ .env/Secrets 미변경

✅ DB 연결/운영 DB 로직 미변경

✅ DB 스키마 미변경

✅ 스타일/레이아웃/Tailwind/컴포넌트 구조 미변경

리스크와 회피책

호환 리스크: 경로/응답 포맷 불일치로 일부 화면 회귀 버그

회피: Alias 우선으로 양쪽 호환, 프론트 치환은 마지막 수단

성능/보안: 새 미들웨어/검증 추가로 예상치 못한 401/403, 지연

회피: 기존 미들웨어 구성 유지, 입력 검증은 현 수준 유지(추가 도입 금지)

롤백 계획

빠른 롤백: 이번 변경 커밋 1건으로 묶음 → 문제 시 해당 커밋만 revert

파일 단위 복원: 위 4개 파일만 직전 버전으로 체크아웃

절차: 복원 → npm run build → 서버 재시작 → 동일 시나리오 재검증

검증 시나리오 & 성공 기준
E2E-1. 로그인 & 접근

관리자 로그인 → AdminPanel 진입

성공: 200 OK, 콘솔 오류 0

E2E-2. 기타 업무 통신사 생성

필수 필드 입력 → “생성” 클릭

Network: POST /api/other-business-carriers(기존 경로) 200/201

UI 목록 즉시 반영(또는 invalidateQueries 후 갱신)

성공: 응답 포맷 기존과 동일, 테이블에 신규 1건 표시

E2E-3. 사용자 생성

새 사용자 폼 제출

POST /api/auth/users (또는 기존 사용 경로) 200/201

성공: 목록에 신규 사용자 표시, 콘솔 오류 0

E2E-4. 새 요금제 생성

새 요금제 폼 → “생성”

POST /api/service-plans 200/201

성공: 목록에 신규 요금제 1건 표시

E2E-5. 회귀 테스트(다른 화면 영향 없음)

완료/기타완료/접수/대시보드 모두 200, 기존 데이터 표시 정상, 콘솔 오류 0

최종 성공 조건

각 생성 요청 200/201, 프론트 무수정 또는 최소 한 줄 치환으로 정상 동작

테이블 반영 확인(신규 1건)

콘솔/서버 로그 에러 0

운영 테스트 요청에 대한 답변

바로 운영(mccnetworld.com) 테스트는 보류: 먼저 테스트페이지에서 E2E-1~5 전부 통과 → 그 다음 운영 동일 시나리오 수행 권장.

운영 테스트 시에는 변경 커밋/배포 버전을 명시하고, Network 캡처(요청/응답, 상태코드, 응답 바디)와 테이블 반영 스크린샷을 함께 확보해 주세요.
