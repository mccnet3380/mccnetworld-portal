수정 목적 (한 줄)

접수관리의 **개통 상태 드롭다운에 ‘기타완료’**를 추가하고, 선택 시 해당 건을 기타 업무 처리건으로 집계되도록 연동.

해결할 오류 / 재현 절차 (간단)

현재: 상태 변경 모달에 ‘기타완료’ 옵션 부재 → 기타 업무 완료 흐름/집계 불가.

재현:

접수관리 → 임의 문서 선택 → 개통 상태 변경

드롭다운에 ‘대기/진행중/업무요청중/개통/폐기’만 존재

대시보드 ‘기타 업무 처리건’ 수치에 반영 불가

변경 범위 요약

프론트엔드: Documents.tsx 상태 드롭다운에 ‘기타완료’ 항목 1줄 추가 (UI/스타일/구조 불변)

백엔드:

상태 업데이트 라우트에서 ‘기타완료’ 허용 및 처리자/처리시각 자동 기록(세션 기반)

대시보드/목록 집계에 ‘기타완료’ 포함(당일/당월 통계에서 분리 집계)

빌드/배포: npm run build 후 서버 재시작 (테스트/운영 동일)

불변: 환경변수/Secrets·DB 스키마·CSS/Tailwind·레이아웃 모두 미변경

파일 경로 + 파일별 변경 이유

client/src/pages/Documents.tsx

개통 상태 드롭다운 옵션 목록에 기타완료 1개 추가 → 선택/저장 시 기존 mutation이 동일 페이로드로 전송.

server/routes.ts

상태 업데이트 라우트(예: PATCH /api/documents/:id/activation-status)의 허용 상태 집합에 기타완료 추가.

상태가 기타완료일 때 activated_by(세션 userId), activated_at(now) 자동 세팅(프론트 의존 X).

server/storage.ts

대시보드 집계 메서드(getTodayStats, 월별/분류 집계 등)에서

‘당일 개통건’: 개통/개통완료만 포함, 기타완료는 제외

‘기타 업무 처리건’: activation_status='기타완료'만 집계

문서 목록 조회 시 activationStatus=기타완료 필터 동작 재확인(필요 시 where 추가).

예상 변경 내용 (요약 diff — 개념)

Documents.tsx

상태 셀렉트 옵션에 기타완료 1줄 추가.

routes.ts

허용 상태: {대기, 진행중, 업무요청중, 개통, 폐기 **, 기타완료**}

기타완료로 변경 시:

activated_by = req.session.userId

activated_at = now() (KST 변환은 기존 로직 유지)

storage.ts

오늘/월 집계:

otherCompletedToday = COUNT WHERE activation_status='기타완료' AND activated_at ∈ 오늘(KST)

‘당일 개통건’은 activation_status IN ('개통','개통완료') 또는 activated_at NOT NULL AND status != '기타완료'로 명확 분리.

핵심 추가/삭제/치환 포인트

➕ 드롭다운 옵션 기타완료 추가(프론트 1줄)

➕ 라우트 허용 상태에 기타완료 추가

➕ 기타완료 시 처리자/처리시각 자동 기록(세션 기반)

➕ 대시보드 ‘기타 업무 처리건’ 집계에서 기타완료 카운트

➖ 다른 상태/집계 로직 변경 없음(분리 유지)

환경변수/DB/스키마/스타일 미변경

✅ .env/Secrets/DB 연결/운영 DB 로직 변경 없음

✅ DB 스키마 변경 없음

✅ UI/레이아웃/스타일 변경 없음(옵션 1줄만 추가)

리스크와 회피책

집계 혼선 리스크: ‘개통’과 ‘기타완료’ 조건 분리를 storage 레이어에서 보장.

처리자 누락 리스크: 서버가 세션 기반으로 강제 기록(프론트 의존 X).

검증 시나리오 & 성공 기준

S1. 상태 변경(엔드투엔드)

절차: 로그인 → 접수관리 → 문서 선택 → 개통 상태 ‘기타완료’ 저장

기대: 200 응답, 목록에서 상태가 ‘기타완료’, 서버 로그 에러 없음

DB 확인: activation_status='기타완료', activated_by=내 ID, activated_at 저장

S2. 기타 페이지 반영

절차: 기타(기타완료) 페이지 이동

기대: 방금 건이 목록에 표시(처리자 이름 포함 시 정상)

S3. 대시보드 집계

절차: 대시보드 진입/새로고침

기대: ‘기타 업무 처리건’ 수치 +1, ‘당일 개통건’은 변동 없음

S4. 회귀(다른 상태 영향 확인)

절차: 다른 문서를 **‘개통’**으로 저장

기대: ‘당일 개통건’만 증가, ‘기타’ 미증가
