수정 완료 후 동일 시나리오로 재검증하여 에러/이상 여부 확인할 것.

사전 변경 가이드(무엇을 어떻게 바꿀지 명확히)

변경 전(잘못된 현재 로직):

세션 생성/조회/삭제 시 auth_sessions 혹은 존재하지 않는 테이블을 참조하거나, sessions 스키마와 다른 필드 사용.

변경 후(정상):

shared/schema.ts의 sessions 테이블만 사용:

sid: string(primary key)

sess: jsonb(사용자·권한·만료 정보 등 JSON)

expire: timestamp(만료 시각)

세션 생성:

sid = nanoid(), sess = { userId, userType, managerId?, teamId?, userRole?, createdAt, expiresAt }, expire = Date(지금+24h)

세션 조회:

select * from sessions where sid = :sid

expire 지났으면 삭제 후 null 반환

세션 삭제:

delete from sessions where sid = :sid

응답/로깅에서 민감 토큰은 반드시 마스킹 처리.

해야 할 일(정확한 요청)

세션 관련 코드 전수 조사: auth_sessions 또는 세션 로직이 흩어져 있는 파일 식별

예상 파일: server/storage.ts(필수), 필요 시 server/routes/auth.ts 또는 세션을 직접 만지는 서비스 파일

모든 세션 접근을 sessions 테이블로 교체하고, 아래 규격에 맞게 구현/정리

createSession(userId:number, userType:string, managerId?:number, teamId?:number, userRole?:string): Promise<string>

getSession(sessionId:string): Promise<any>

deleteSession(sessionId:string): Promise<void>

위 3개는 반드시 sessions(sid, sess:jsonb, expire:timestamp) 만 사용

로그인 흐름 점검

관리자/영업과장/근무자 로그인 → createSession 호출 → sid를 토큰처럼 반환

/api/auth/me 등 세션 확인 API는 Authorization: Bearer <sid> 로 getSession 통과해야 정상

파일 반환 규칙 준수

CHANGED_FILES 목록과 함께, 각 수정 파일은 “전체 최종본 코드” 로만 반환(부분코드 금지)

출력 형식(반드시 준수)

CHANGED_FILES: 수정된 파일 경로 목록

각 파일은 아래 형태로 전체 최종본 제공
