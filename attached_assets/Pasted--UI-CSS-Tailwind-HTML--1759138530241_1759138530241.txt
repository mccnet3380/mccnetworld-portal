변경 개요

수정 목적: 개통완료 관리 테이블의 처리자 컬럼에서 사용자명이 비어 있거나 -로 나오는 문제를 해결하여 정확한 처리자명 표시.

해결할 오류 / 재현 절차(간단)

현상: “처리자” 컬럼이 - 또는 빈 값으로 표시됨.

재현: /completed-activations 페이지 → 테이블 확인.

추정 원인:

문서 객체의 처리자 키가 환경마다 다름: activated_by, activatedBy, activatorId, processed_by 등 혼재.

ID 타입 불일치(숫자 vs 문자열)로 사용자 목록과 매칭 실패.

일부 응답에 processedByName 또는 activated_by_name가 존재하나 사용 안 함.

변경 범위 요약

프론트엔드만 수정: 처리자 표시 로직(매핑/폴백) 개선.

백엔드/빌드/배포/환경변수/스타일/레이아웃: 변경 없음(빌드·배포는 실행 필요).

수정 파일 목록 (최소화)

client/src/pages/CompletedActivations.tsx

파일 경로 + 파일별 변경 이유

CompletedActivations.tsx

getActivatedByNameSync(또는 동등 유틸)에서 다중 키 폴백 + 타입 정규화로 사용자 매칭 정확도 향상.

사용자 목록을 Map 캐싱(useMemo) 하여 O(1) 조회 및 성능 유지.

예상 변경 내용 (요약 diff)

[추가] 사용자 맵 캐싱

const userMap = useMemo(() => {
  return new Map(users.map(u => [String(u.id), u.name]));
}, [users]);


[치환] 처리자 ID 정규화 + 다중 키 폴백

const resolveActivatorId = (doc:any) =>
  doc?.activated_by ?? doc?.activatedBy ?? doc?.activatorId ?? doc?.processed_by ?? null;

const activatorId = resolveActivatorId(doc);
const activatorName =
  doc?.activated_by_name ??
  doc?.processedByName ??
  (activatorId != null ? userMap.get(String(activatorId)) : undefined) ??
  '-';


[유지] 렌더링/레이아웃/스타일 및 다른 컬럼 로직 그대로 유지

핵심 추가/삭제/치환 포인트 요약
