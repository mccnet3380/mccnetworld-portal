역할: 너는 숙련된 풀스택 엔지니어다. 
절대 조건: UI/레이아웃/디자인/Tailwind 클래스, .env/Secrets, DB 연결/스키마는 어떤 경우에도 변경 금지. 
출력 규칙: 
1) 먼저 “사전 변경 안내”만 제출(아래 양식). 
2) 내가 승인하면 각 파일 “전체 최종본”을 제출(부분 코드 금지). 
3) 수정 전/후 동일 시나리오 재검증 로그를 함께 제출. 
4) 개발(replit)과 운영(republish 후)에서 동작이 100% 동일해야 함.

[현재 증상]
- 운영 페이지: 
  ① 개통방명 코드 입력 시 자동완성 검색 기능 동작 안 함(제안 리스트 X). 
  ② 접수 신청 시 “Upload failed with status 400” 알림으로 접수 실패. 
- 개발( Replit ) 페이지: 
  ① 개통방명 코드 자동완성은 동작함. 
  ② 접수 버튼 클릭 시 “파일 선택” 토스트만 뜨고 접수되지 않음. 
- 즉, 운영/개발의 결과가 서로 다름. 두 환경 모두 동일하게 정상 작동하도록 동기화 필요.

[해야 할 일(코드 제출 금지, 계획만 먼저)]
1) “검색 기능” 동기화:
   - 운영/개발 모두 동일한 API 경로와 동일한 쿼리 로직 사용.
   - 서버에 개별 코드 검색 라우트가 없다면 추가(기존 라우트 유지, 하위 호환).
   - 프론트 2개 화면(SubmitApplication, AdminPanel)의 검색 호출 방식을 일치.
2) “접수 신청” 동기화:
   - 파일 업로드를 선택사항으로 처리(파일 없어도 접수 가능).
   - 서버 라우트에서 파일 미첨부 시 400을 내던 로직 제거(단, 기존 파일 업로드 기능은 유지).
   - 프론트에서 파일 유무 관계 없이 동일 엔드포인트/폼데이터 처리, 토스트 메시지 오작동 제거.
3) 운영용 코드와 Replit 개발 코드가 분리되어 있다면 “두 코드베이스를 모두” 수정하고, 동일 빌드/배포 시 결과 일치 보장.

[수정 범위(예상)]
- 서버: 검색/접수 관련 라우트만 최소 수정(새 라우트 추가 또는 검증 로직 보정). 
- 프론트: 검색/접수 관련 2개 페이지 로직만 최소 수정. 
- 빌드/배포: 현행 파이프라인 유지(설정 변경 금지).

[검증 시나리오 & 성공 기준(필수)]
1) 검색 자동완성:
   - 입력란에 “L” 타이핑 → 제안 목록 표시, 항목 선택 시 판매점명 자동 입력.
   - 운영/개발 동일 결과. 
   - 성공: 네트워크 200, 콘솔 에러 0, 두 환경 동일 UI/동작.
2) 접수(파일 없음):
   - 필수값만 입력 후 “접수 신청” → 정상 등록.
   - 성공: 응답 201/200, “Upload failed with status 400” 미발생, 리스트/DB 반영 확인.
3) 접수(파일 있음):
   - 파일 첨부 후 “접수 신청” → 정상 등록 및 파일 경로 저장.
   - 성공: 응답 201/200, 파일 메타 저장 확인, 콘솔 에러 0.
4) 환경 동등성:
   - Replit 개발 서버와 Republish 후 운영 페이지에서 위 1)~3) 동일 결과.
