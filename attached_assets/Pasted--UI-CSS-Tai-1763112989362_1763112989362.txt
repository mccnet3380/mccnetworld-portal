오류가 발생한 부분만 수정 (불필요한 변경 금지)

UI(레이아웃/디자인/스타일/컴포넌트 구조)는 절대 변경 금지

버튼 색상, CSS, Tailwind 클래스, HTML 구조는 그대로 유지

환경설정(.env, Secrets, DB 연결, 운영 DB 로직)은 절대 수정 금지

DB 스키마 변경은 금지 → 필요 시 “코드 수정 없이” ‘DB 스키마 변경 제안’ 섹션으로 설명만 제시

부분 코드 금지 → 반드시 “파일 전체 최종본” 제출

내가 즉시 복붙 가능해야 함 (불필요한 설명 최소화)

추측/가정 금지 → 실제 오류 재현 → 필요한 최소 범위만 수정

⚠️ 수정 후 반드시 서버 재시작 및 동일 시나리오 재검증

⚠️ 코드 제출 전후로, 같은 시나리오에서 오류 없는지 다시 확인

⚠️테스트페이지(neon 데이터베이스 운영)과 운영서버(mccnetworld.com)(render 데이터 베이스 운영)에 대해 코드 정확하게 수정 할것

4) 수정 파일 목록 (최소화)

server/auth-routes.ts

변경 이유: dealer 로그인시 적절한 인증 함수 호출/검증 로직 보정

server/storage.ts (필요 시에만)

변경 이유: dealer 전용 조회 조건(userType='dealer' + bcrypt.compare) 보정

UI/CSS/.env/스키마/프론트 라우팅은 절대 변경하지 마세요.

5) 예상 변경 내용 (요약 diff)

auth-routes.ts (POST /api/auth/dealer-login)

const { username, password } = req.body;

저장소 함수 호출 시 dealer 한정 조회(예: authenticateUser(username, password, 'dealer') 또는 authenticateDealer(...))

성공 시:

res.json({ success: true, user: { id, username, name, role: 'dealer' }});


실패 시:

res.status(401).json({ success:false, error:'아이디 또는 비밀번호가 올바르지 않습니다.' });


storage.ts (필요 시)

authenticateUser(또는 새 authenticateDealer)에서:

SELECT ... FROM users WHERE username=? AND user_type='dealer'

bcrypt.compare(plain, hashed) 결과로 판정

is_active 확인(있다면)

6) 리스크와 회피책

리스크: admin/employee와 dealer 계정 영역이 섞이면 다른 라우트 영향 가능

회피: 조회 시 반드시 userType='dealer' 또는 테이블 분리로 강제 가드. 기존 라우트/로직 건드리지 않음.
