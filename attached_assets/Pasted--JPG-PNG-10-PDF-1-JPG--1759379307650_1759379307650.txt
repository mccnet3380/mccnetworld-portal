접수 신청에서 JPG/PNG 이미지는 최대 10장, PDF는 1개만 업로드되도록 제한하고, 서버도 동일 규칙으로 검증.

해결할 오류 / 재현 절차

현재: JPG 여러 장 선택해도 1개만 올라가거나, PDF 다중 선택 시 제약 없음

재현:

접수 신청 페이지 진입

파일 선택(여러 JPG 또는 여러 PDF)

기대: JPG/PNG ≤ 10장, PDF ≤ 1개. PDF가 포함되면 PDF 단독 1개만 허용

변경 범위 요약

프론트엔드: client/src/pages/SubmitApplication.tsx

파일 입력을 다중 선택 허용으로 전환

선택 즉시 클라이언트 측 개수/형식 검증 (PDF 단독 1개, 이미지 최대 10장)

FormData에 모든 파일을 동일 필드명으로 추가(서버 기대명 유지)

⚠️ UI/레이아웃/스타일 변경 없음 (파일 목록 표시는 추가하지 않음)

백엔드: server/routes.ts

POST /api/documents 업로드 라우트에서 다중 파일 수신 활성화

업로드 직후 서버 측 검증(PDF 1개, 이미지 ≤10장, 혼합 불가) 추가

규칙 위반 시 400 반환, 메시지 명확히

불변: 환경변수/DB 스키마/운영 DB 로직/스타일

수정 파일 목록 (최소화)

client/src/pages/SubmitApplication.tsx

server/routes.ts

파일별 변경 이유 (각 1–2줄)

SubmitApplication.tsx: 파일 다중 선택 허용 및 선택 시 즉시 제한 검증으로 불필요한 서버 왕복 방지. FormData에 모든 파일 추가.

routes.ts: 서버 기준의 최종 보안 검증(클라이언트 우회 대비). 검증 통과분만 저장/문서 생성.

예상 변경 내용 (요약 개념)
프론트(개념)

파일 input: multiple 활성화(accept은 기존 유지: .pdf,.jpg,.jpeg,.png)

onChange 시 파일 배열을 분류:

pdfCount = type === 'application/pdf'

imageCount = type.startsWith('image/')(jpg/png만 통과)

검증 규칙:

pdfCount > 1 ⇒ 차단(“PDF는 1개만 업로드 가능합니다.”)

pdfCount === 1 && imageCount > 0 ⇒ 차단(“PDF는 단독 1개만 업로드 가능합니다.”)

imageCount > 10 ⇒ 차단(“이미지는 최대 10개까지 업로드 가능합니다.”)

FormData: 서버가 기대하는 단일 필드명(예: files)에 선택된 모든 파일을 순서대로 append

제출 시 기존 필드들과 함께 전송, UI는 현행 유지(버튼/레이아웃 변경 없음)

백엔드(개념)

업로드 미들웨어: 다중 파일 수신 허용(formidable/멀터 설정에서 multiples true 등, 현 프로젝트 기준 유지)

업로드된 파일 메타에서 MIME 분류 → 위와 동일 규칙으로 검증

위반 시 400 + 사유 메시지 반환(프론트 토스트로 그대로 노출)

통과 시 파일 개수만큼 문서 레코드 생성(기존 생성 로직 재사용, 스키마 변경 없음)

리스크와 회피책

대용량 업로드 부하: 클라이언트에서 사전 차단 + 서버에서 10장/1개 상한으로 제한

혼합 업로드 시 사용자 혼란: 에러 메시지를 정확한 한글 고지(PDF는 단독 1개, 이미지는 최대 10장)

롤백 계획

SubmitApplication.tsx, server/routes.ts만 직전 버전으로 복원 → 재빌드/재시작
