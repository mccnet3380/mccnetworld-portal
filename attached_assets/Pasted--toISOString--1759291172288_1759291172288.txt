접수 관리 모달 저장 시 날짜 필드 직렬화 오류(빈 값·문자열에 .toISOString() 호출)를 방지하여 정상 저장되도록 복구.

해결할 오류 / 재현 절차(간단)

오류 증상: 접수 관리 > 행 클릭 → 편집 모달 → 저장 → 우하단 토스트: 오류 value.toISOString is not a function

재현: 날짜 입력 없이 저장(또는 날짜를 선택 후 해제) 시 100% 재현

원인: 저장 핸들러에서 value.toISOString()을 직접 호출(값이 ''/string/undefined일 때 런타임 에러)

추가(유틸 함수 한 개)

toISOOrNull(value)

null/undefined/'' → null

value instanceof Date → value.toISOString()

typeof value.toDate === 'function'(dayjs 등) → value.toDate().toISOString()

typeof value === 'string' → 유효 파싱 시 new Date(value).toISOString() / 무효면 null

치환(저장 페이로드 구성)

기존: form.startDate.toISOString() → 변경: toISOOrNull(form.startDate)

동일 패턴으로 모든 날짜 필드에 적용:

시작일/종료일, 가입일, 유심비 결제일, 결합 시작일, 희망일, 생년월일, 기타 날짜형 필드

유지

날짜가 null이면 필드를 생략하거나 서버에서 허용하는 빈 값으로 전송(현재 프로토콜 유지)

activated_at은 서버가 자동 세팅(개통/기타완료 전환 시)

핵심 추가/삭제/치환 포인트 (불릿)

추가: 안전 직렬화 유틸 toISOOrNull (파일 내부에 로컬 함수로 추가)

치환: 모든 .toISOString() 직접 호출 → toISOOrNull() 경유

유지: UI/레이아웃/Tailwind/컴포넌트 구조, 라우트, 응답 파싱 로직 그대로

리스크와 회피책

타임존 해석 차이: 문자열 YYYY-MM-DD를 파싱 시 UTC 기준 시차 발생 가능

회피: 로컬 날짜만 있는 문자열은 T00:00:00+09:00(KST)로 보정 후 ISO 변환(유틸 내부 처리)

서버 검증 실패: 필수 날짜를 null로 보내면 400 가능

회피: 기존 필드의 필수/선택 여부 유지. 필수면 저장 전 UI 유효성 검사 그대로.
