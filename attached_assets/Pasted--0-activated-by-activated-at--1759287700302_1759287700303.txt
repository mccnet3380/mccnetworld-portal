수정 목적(한 줄)

대시보드가 여전히 0/빈값을 반환하고, 개통/기타완료 처리 시 activated_by/activated_at 저장이 누락되는 문제를 서버/클라이언트 최소수정으로 즉시 복구.

현재 증상 & 재현 (테스트/운영 동일)

대시보드

관리자/근무자 로그인 → 대시보드 진입 → 당일 접수건/개통건/당월 현황 모두 0

Network: /api/dashboard/* 200이지만 내용 0/빈배열

개통완료 관리 테이블

실제 개통완료 문서 다수 존재(48건 등)

처리자/당월 요금제 변경 컬럼이 ‘-’ 또는 공란

DB 확인(예: id=52, ‘실적테스트’)

activated_by, activated_at NULL (재처리 안내 후에도 값 안 들어옴)

원인(가설) 요약

서버 대시보드 API가 응답 키/타임존/상태 매핑이 프론트 기대와 불일치 → 0 표시

개통 처리 시 프론트 요청 본문에 activatedBy/activatedAt 누락 또는 서버에서 세션→컬럼 매핑 누락

컬럼명 불일치: created_at이 아닌 **uploaded_at**을 사용해야 함 (Asia/Seoul 기준 집계)

캐시 문제: 대시보드 API가 캐싱되어 이전 0 응답 재사용 가능

변경 범위 요약 (최소)

백엔드(필수)

PUT /api/documents/:id/activation-status

요청 본문에 activatedBy가 없어도 서버가 세션에서 userId 추출해 activated_by로 저장

activationStatus가 **‘개통’, ‘개통완료’, ‘기타완료’**로 전환될 때 activated_at=now(Asia/Seoul) 저장

기존 필드/응답 포맷 불변

대시보드 API 4종(/today-stats, /monthly-activation-stats, /carrier-stats, /worker-stats)

집계 쿼리에서 uploaded_at + Asia/Seoul 적용

상태 매핑: 개통/개통완료/기타완료를 집계에 포함(화면 요구에 맞춤)

프론트가 기대하는 기존 키명으로 정규화 후 반환

헤더: Cache-Control: no-store, Vary: Cookie (캐시 금지)

사용자 컨텍스트

req.user || req.session.user || req.session.userId/role 등 다중 소스 병합으로 userId/userType 추출 (근무자=본인, 영업과장=팀, 관리자=전체)

프론트엔드(필요 최소)

개통/기타완료를 발생시키는 모든 진입점에서(예: CompletedActivations.tsx의 DeviceEditDialog, AdminPanel.tsx의 상태 변경, OtherApplication.tsx의 기타완료 생성)

요청 본문에 activatedBy 포함(가능 시)

단, 서버가 세션 우선으로 저장하도록 했으므로 클라 미전송 시에도 저장되어야 함

대시보드 화면 코드는 무변경(서버가 응답 키를 맞춤)

빌드/배포

dist/빌드 캐시 삭제 후 재빌드 & 서버 재시작

배포형(Deployment)이면 배포물 커밋/빌드시간 일치 확인 & 필요 시 동일 커밋 재배포

CDN/Service Worker 캐시 퍼지(no-store 헤더 적용 확인)

불변: 환경변수/Secrets, DB 스키마, UI/레이아웃/스타일
